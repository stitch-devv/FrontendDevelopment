# Урок 04 — Git и GitHub

# Цель урока

Понять:

* что такое Git;
* что такое GitHub;
* зачем они нужны;
* что такое repository;
* что такое commit;
* что такое push и pull.

---

# 1. Зачем нужен Git?

Представь, что ты работаешь над сайтом и ты изменил код. Каждый раз когда ты меняешь код, оно сохранятеся в определенной система - **Git**. Git позволяет сохранять историю изменений проекта.

---

# 2. Что такое Git?

*Git* — система контроля версий. Она нужна для записи истории изменений файлов и совместной работы над кодом

Она позволяет:

* сохранять изменения;
* смотреть историю;
* возвращаться к старым версиям;
* работать в команде;
* создавать отдельные ветки;
* объединять изменения.

---

# 3. Что такое GitHub?

*GitHub* — онлайн-платформа, где можно хранить Git-репозитории.
Git работает локально на твоём компьютере и позволяет хранить проект онлайн.

---

# 4. Git и Github: в чем разница?

*Git* — это программа (консольная утилита) для отслеживания изменений в коде на вашем компьютере. Она работает локально на компьютере. Умеет:
* Записывать историю всех изменений в файлах проекта;
* Позволяет создавать отдельные ветки для доработки функций;
* Дает возможность откатить код к любой рабочей версии, если что-то сломалось;
* Работает без интернета и без привязки к каким-либо сайтам;

*GitHub* — это облачный веб-сервис для хранения кода в интернете и совместной работы над ним. Она работает в браузере(в облаке). Умеет:
* Хранить копию вашего кода на удаленном сервере (в облаке);
* Позволяет нескольким людям одновременно работать над одним проектом;
* Предоставляет инструменты для обсуждения кода;
* Показывает ваш профиль с историей проектов(полезно для портфолио программиста);


# 5. Repository

*Repository(репозиторий)* — место, где хранится проект и история его изменений. С английского переводится как 'хранилище'. Вы всегда можете посмотреть, кто, когда и какие строки кода изменил, а при необходимости — вернуться к любой из прошлых версий программы.
Несколько программистов могут одновременно работать над одним проектом, не перезаписывая файлы друг друга, а система помогает объединять их правки.
### Код хранится не только на компьютере разработчика, но и на сервере. Если ПК сломается, проект не потеряется.

---

# 6. Commit

*Commit* — сохранение определённого состояния проекта в истории Git. Простыми словами, коммит — это контрольная точка или сохраненная страница в истории проекта. Можно представить commit как контрольную точку.


### Из чего состоит коммит в Git

• Уникальный хеш-код (длинный набор букв и цифр) для идентификации определнной версии;
• Автор (имя и электронная почта того, кто внес правки);
• Дата и время создания;
• Сообщение коммита — текстовое описание того, какие именно изменения были сделаны;
• Ссылка на родительский коммит — указание на то, из какой версии выросла эта правка;

---

# 7. Push

*Push* отправляет локальные изменения на GitHub.

---

# 8. Pull

*Pull* получает изменения с GitHub на компьютер.

---

# Запомни

Git → система контроля версий

GitHub → онлайн-платформа для Git

Repository → репозиторий проекта

Commit → сохранённая версия

Push → отправить изменения

Pull → получить изменения

---
